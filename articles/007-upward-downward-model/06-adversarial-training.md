# 06｜真正對抗式雙模型

## 6.1 你要的不是 solver-verifier

Solver-Verifier 架構是一個模型解題、另一個模型驗證。但這有根本問題：

- Verifier 只能檢查 solver 的輸出是否「看起來正確」
- Verifier 沒有自己的答案，無法發現 solver 遺漏的路徑
- 兩者不對稱：solver 有完整資訊，verifier 只有片段

---

## 6.2 真正對抗式雙模型

你提出的不是 solver-verifier，而是：

```
下行模型 D↓：從目的生成答案
上行模型 U↑：從結果反推目的再生成答案
兩者在同一目的向量下對抗
多 judge 評分
meta-synthesizer 重組
再拆成上下兩種格式回訓
```

關鍵差異：

1. **兩個模型都產生答案**，不是一個生、一個審
2. **對抗的不是真假，而是目的對齊**：兩者的答案是否收斂到同一目的
3. **分歧是主要輸出**：當兩者不一致時，分歧本身是系統對不確定性的感測器
4. **回訓是雙向的**：分歧樣本同時改善下行和上行模型

---

## 6.3 對抗流程

```
1. 給定 purpose vector P
2. D↓ 從 P 生成答案 A_d
3. U↑ 從 A_d + 軌跡反推 P'，再生成答案 A_u
4. 多 judge 評分：A_d 與 A_u 的品質、一致性、目的對齊
5. 若 A_d 與 A_u 收斂 → 輸出合成答案
6. 若 A_d 與 A_u 分歧 → 分歧分類 → 不確定性評估 → bounded next dispatch
7. 分歧樣本回訓 D↓ 和 U↑
```

---

## 6.4 分歧不是失敗

在傳統系統中，分歧代表錯誤。但在這個框架中：

> **分歧是系統對自身不確定性的主要感測器。**

- 當 D↓ 和 U↑ 一致時，系統可以自信輸出
- 當 D↓ 和 U↑ 分歧時，系統知道自己在某個維度上不確定
- 分歧的類型（route 分歧？numeric 分歧？purpose 分歧？）決定了下一步行動

---

## 6.5 與 GAN 的本質差異

| 面向 | GAN | 007 雙模型 |
|------|-----|-----------|
| 目標 | 生成器騙過判別器 | 兩者都對齊到同一目的 |
| 輸出 | 生成器產生的假資料 | 兩者都產生合法答案 |
| 對抗本質 | 真假分類 | 目的對齊 |
| 分歧處理 | 判別器輸出的機率 | 分歧分類 + 不確定性評估 |
| 訓練信號 | 判別器的真假標籤 | 分歧類型 + 目的對齊度 |
