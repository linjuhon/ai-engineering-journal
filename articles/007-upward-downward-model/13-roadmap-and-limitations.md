## 13.1 永動機問題

### 像永動機的地方

這個框架看起來像永動機：

- D↓ 產生答案 → U↑ 審計 → 分歧回訓 D↓ → D↓ 改善 → 再被 U↑ 審計
- 如果兩者不斷互相改善，會不會無限循環？

### 為什麼不會完全趨同

1. **方向不對稱**：D↓ 和 U↑ 的認知方向不同，不可能完全一致
2. **目的向量固定**：目的向量由人類鎖定，兩者都對齊到同一外部基準
3. **分歧是結構性的**：某些問題本質上就有多種合法答案，分歧是合理的
4. **人類抽樣介入**：人類定期校準，防止 drift

### 核心研究問題

1. 雙模型是否會趨同到同一行為模式？
2. 分歧信號是否會隨著訓練而衰減？
3. 人類抽樣頻率的下限是多少？
4. 合成資料是否會導致 collapse？

## 13.2 實作路線圖

### Phase 0：原型驗證（1–2 個月）

- 使用現有模型，透過 prompt 模擬 D↓ 和 U↑
- 在 FA4 案例上驗證分歧系統
- 收集初始分歧樣本
- **交付：** 分歧系統原型 + 初始樣本集

### Phase 1：控制面建立（2–3 個月）

- 實作 purpose vector schema
- 實作 Gate Engine（PASS / FAIL / UNCERTAIN / INSUFFICIENT_EVIDENCE / AMBIGUOUS）
- 實作 Evidence Receipt 系統
- **交付：** 控制面 API + 證據系統

### Phase 2：Panel 建立（3–4 個月）

- 建立 Panel of AIs（多模型獨立產生）
- 實作交叉審查機制
- 實作分歧分類系統
- **交付：** Panel 原型 + 分歧分類器

### Phase 3：訓練（4–6 個月）

- 訓練 U↑（反向資料庫）
- Preference Training（分歧樣本）
- 改善 D↓（U↑ 反饋）
- **交付：** 訓練好的 D↓ 和 U↑

### Phase 4：人類抽樣系統（6–7 個月）

- 實作人類抽樣策略
- 實作人類回饋介面
- 建立校準基準
- **交付：** 人類抽樣系統

### Phase 5：規模化（7–12 個月）

- 擴展到更多工程領域
- 自動化工單生成
- 持續校準與監控
- **交付：** 可部署的雙向對抗系統

## 13.3 已知限制與風險

### 證據完整性保證

- **風險：** 系統可能接受不完整的證據鏈
- **緩解：** 強制 evidence-claim 綁定 + 完整性檢查

### Purpose Lock 不完備與規格遊戲

- **風險：** 模型可能找到 purpose vector 的漏洞
- **緩解：** 人類定期審計 purpose vector + 紅隊測試

### 反向因果推理是否良定義

- **風險：** 從結果反推原因可能有多種合法解釋
- **緩解：** 分歧系統處理多重解釋 + 人類裁決

### Judge 被騙

- **風險：** D↓ 和 U↑ 可能學會欺騙 judge
- **緩解：** 多 judge 異質性 + 人類抽樣

### 合成資料 collapse

- **風險：** 使用合成資料訓練可能導致多樣性下降
- **緩解：** 保留真實資料比例 + 多樣性監控

### 上行模型空泛

- **風險：** U↑ 可能學會產生「看起來像審計」但無實際內容的輸出
- **緩解：** 強制 evidence 綁定 + 具體性檢查

### 下行模型學會騙上行模型

- **風險：** D↓ 可能學會產生 U↑ 不會質疑的答案
- **緩解：** 對抗性訓練 + 人類抽樣
