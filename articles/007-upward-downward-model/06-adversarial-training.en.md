# 06 | True Adversarial Dual-Model

> **Maturity:** PROVISIONAL (architecture finalized; training not yet implemented)
> **Corresponding source section:** Part VI (True Adversarial: Not One Generates, One Reviews)

---

## 6.1 What You Want Is Not a Solver-Verifier

The Solver-Verifier architecture has one model solve and another model verify. But this has a fundamental problem:

- The Verifier can only check whether the solver's output "looks correct"
- The Verifier does not have its own answer and cannot discover paths the solver missed
- The two are asymmetric: the solver has complete information, the verifier only has fragments

---

## 6.2 True Adversarial Dual-Model

What you propose is not a solver-verifier, but:

```
Downward Model D↓: generates answers from purpose
Upward Model U↑: reverses purpose from result, then generates answers
The two compete under the same purpose vector
Multi-judge scoring
Meta-synthesizer reorganization
Then split back into two formats for retraining
```

Key differences:

1. **Both models produce answers** — not one generates and one reviews
2. **The adversarial element is not truth vs. falsehood, but purpose alignment**: whether both answers converge to the same purpose
3. **Divergence is the primary output**: when the two are inconsistent, the divergence itself is the system's sensor for uncertainty
4. **Retraining is bidirectional**: divergence samples improve both the downward and upward models

---

## 6.3 Adversarial Flow

```
1. Given purpose vector P
2. D↓ generates answer A_d from P
3. U↑ reverses P' from A_d + trace, then generates answer A_u
4. Multi-judge scoring: quality, consistency, and purpose alignment of A_d and A_u
5. If A_d and A_u converge → output synthesized answer
6. If A_d and A_u diverge → divergence classification → uncertainty assessment → bounded next dispatch
7. Divergence samples retrain D↓ and U↑
```

---

## 6.4 Divergence Is Not Failure

In traditional systems, divergence represents error. But in this framework:

> **Divergence is the system's primary sensor for its own uncertainty.**

- When D↓ and U↑ are consistent, the system can output with confidence
- When D↓ and U↑ diverge, the system knows it is uncertain along some dimension
- The type of divergence (route divergence? numeric divergence? purpose divergence?) determines the next action

---

## 6.5 Essential Differences from GAN

| Aspect | GAN | 007 Dual-Model |
|--------|-----|----------------|
| Goal | Generator fools discriminator | Both align to same purpose |
| Output | Fake data generated by generator | Both produce legitimate answers |
| Adversarial essence | True/false classification | Purpose alignment |
| Divergence handling | Probability output by discriminator | Divergence classification + uncertainty assessment |
| Training signal | True/false labels from discriminator | Divergence type + purpose alignment degree |
