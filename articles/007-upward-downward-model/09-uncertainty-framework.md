# 09｜不確定性直面框架

> **成熟度：** PROVISIONAL（框架已定義；校準機制需實驗）
> **對應原始章節：** Part XIII + XIV（不確定性直面框架、信心度與校準）

---

## 9.1 框架定位

不確定性直面框架是整個系統的**底層哲學**：

> 系統不是急著產生確定答案，而是先判斷目前是否有足夠證據進入下一層 truth gate；證據不足時，必須誠實 abstain，並發出精確的 bounded next dispatch。

---

## 9.2 核心命題

1. **不確定性不是 bug，而是資訊**：系統的不確定性反映了證據的完整性
2. **不確定性必須被表達，不能被隱藏**：模型不能為了「看起來有用」而編造答案
3. **不確定性必須被校準**：系統的 confidence 必須與實際正確率一致
4. **不確定性必須被管理**：高不確定性時 abstain，中等不確定性時發 dispatch

---

## 9.3 系統總架構

```
Panel of AIs（多模型獨立產生）
  → 交叉審查（比對一致性）
  → 分歧分類（分歧類型 + 不確定性來源）
  → 信心校準（confidence vs accuracy）
  → Gate Engine（PASS / FAIL / UNCERTAIN / INSUFFICIENT_EVIDENCE / AMBIGUOUS）
  → 輸出或 dispatch
```

---

## 9.4 信心度定義

信心度是系統對自己答案正確性的估計，範圍 0.0–1.0。

信心度不是「模型覺得自己對」，而是**校準後的預測正確率**：

- confidence = 0.8 → 在歷史資料中，這類答案的正確率約 80%
- confidence = 0.95 → 在歷史資料中，這類答案的正確率約 95%

---

## 9.5 不確定性來源分類

| 來源 | 定義 | 處理方式 |
|------|------|---------|
| 證據不足 | 缺乏足夠證據支持結論 | 收集更多證據 |
| 證據矛盾 | 不同證據指向不同結論 | 分歧分類 + 人類裁決 |
| 模型能力限制 | 模型無法處理當前任務 | 降級或轉專家 |
| 任務模糊 | 任務描述不明確 | 回人類澄清 |
| OOD | 輸入超出訓練分布 | abstain + 標記 OOD |

---

## 9.6 校準機制

校準的目標是讓 confidence 與 accuracy 一致：

- 若 confidence = 0.8 但 accuracy = 0.6 → 過度自信 → 需要降校準
- 若 confidence = 0.6 但 accuracy = 0.8 → 過度保守 → 需要升校準

校準方法：

1. **溫度校準**：調整 softmax 溫度
2. **分箱校準**：將 confidence 分箱，每箱獨立校準
3. **分歧校準**：利用 D↓ 與 U↑ 的分歧程度作為不確定性信號

---

## 9.7 校準獎懲

訓練時加入校準獎懲：

- 正確答案 + 高 confidence → 獎勵
- 正確答案 + 低 confidence → 輕微懲罰（鼓勵自信）
- 錯誤答案 + 高 confidence → 強烈懲罰（防止過度自信）
- 錯誤答案 + 低 confidence → 輕微獎勵（誠實比假成功好）
- abstain + 正確判斷不確定性 → 獎勵
- abstain + 錯誤判斷不確定性 → 懲罰
