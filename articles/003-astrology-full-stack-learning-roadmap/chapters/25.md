# 25｜Prometheus

**本軌角色**：所有服務與九階段的量化健康證據。


### 01. metric 模型與 pull 架構

**核心問題**：這一章不是只背 API，而是回答「metric 模型與 pull 架構」在整個系統中為何存在、資料從哪裡來、最後流向哪裡。

**代碼建立順序**
1. 先寫輸入／輸出契約與錯誤型別。
2. 再寫最小純核心邏輯，禁止直接依賴 UI、HTTP 或資料庫。
3. 以 adapter 接上框架或外部軟體。
4. 補正常、邊界、失敗三組測試。
5. 最後加入日誌、指標、trace 與部署設定。

**操作與執行邏輯**：學習時必須逐步追蹤「呼叫端 → 25｜Prometheus → 下游依賴 → 回傳值／副作用 → 失敗回退」，並畫出至少一張序列圖。

**本專案對應**：所有服務與九階段的量化健康證據。
