## 5.1 冷啟動五階段

### Phase 0：離線驗證

**目標：** 確認 A 在受控環境中的正確性。

- **進入條件：** 資料準備完成（至少 1,000 筆標註案例）
- **活動：**
  - A 初始訓練（13B Full FT 或 31B DoRA）
  - 在測試集上驗證準確率
  - 建立正確性基準
- **退出條件：** A 在測試集達到 85%+ 準確率
- **關鍵風險：** 測試集不代表真實分布

### Phase 1：人工錨定

**目標：** 建立 C 的初始判斷基準。

- **進入條件：** Phase 0 完成
- **活動：**
  - C 的第一批人工標註（至少 500 篇，覆蓋 50+ 維度）
  - 人類逐篇標註 B 的輸出品質
  - 建立 C 的初始門檻
- **退出條件：** C 的黃燈/紅燈與人類判斷一致率 >80%
- **關鍵風險：** 早期標註者偏差（前 200 篇只做影子記錄）

### Phase 2：影子 C

**目標：** C 在不影響放行的情況下收集誤報與漏報。

- **進入條件：** Phase 1 完成
- **活動：**
  - C 以影子模式運行（報黃燈但不阻擋）
  - 人類持續校準 C 的門檻
  - 收集誤報與漏報案例
- **退出條件：** C 的誤報率 <15%
- **關鍵風險：** 過度保守導致 C 被忽略

### Phase 3：D 輔助治理

**目標：** D 開始協助人類處理黃燈案例。

- **進入條件：** Phase 2 完成
- **活動：**
  - D 的訓練（正例 40%、不需調整 40%、邊界 20%）
  - D 提案 → 人類裁決 → 回測 → Canary → 回滾
  - 建立決策簿
- **退出條件：** D 提案的人類採納率 >60%
- **關鍵風險：** D 學成人類的捷徑

### Phase 4：E 橋接實驗

**目標：** 在不影響主流程的情況下驗證 E 的有效性。

- **進入條件：** Phase 3 穩定運行 3 個月 + 5,000 組對齊資料
- **活動：**
  - E 以影子模式運行
  - 監控 B 的多樣性與 OOD 保真
  - 小流量注入實驗
- **退出條件：** E 不降低 B 的多樣性（多樣性下降 <10%）
- **關鍵風險：** 向量注入壓制 B

## 5.2 前 200 篇影子記錄

早期使用者往往是朋友、測試者或對占星高度投入的人，其點讚標準與未來一般用戶不同。

- 前 200 篇完整記錄所有事件，但不改 C 邊界
- 人類仍是唯一錨點
- 這不是浪費資料，而是先建立偏差基線

## 5.3 自蒸餾門檻

不要用 70 分、偶有亮點的作品回訓 B；那會把早期平庸固定成風格。

- **暫定門檻：** 至少 2,000 篇經人類或穩定評測確認的 80+ 佳作
- **涵蓋範圍：** 不同流派、任務與情緒類型
- **蒸餾資料：** 只保留任務輸入與佳作輸出，移除原始提示詞
- **測試方法：** 先影子模型、盲評、回歸測試，再逐步刪除 Few-Shot

## 5.4 B 的初始訓練策略

| 策略 | 優點 | 缺點 | 建議 |
|------|------|------|------|
| 凍結預訓練權重 | 保留通用能力 | 可能不夠適應占星敘事 | 不建議 |
| LoRA 微調 | 低成本、可切換 | 容量可能不足 | Phase 0 可採用 |
| 全參數微調 | 最大適應性 | 高成本、災難性遺忘風險 | 需實驗驗證 |
| 從零訓練 | 完全控制 | 極高成本、資料需求大 | 不建議初期採用 |

**建議：** Phase 0 先以 LoRA 微調為主，若容量不足再升級為全參數微調。
