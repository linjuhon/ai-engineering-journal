# 04｜線上推理管線

> **成熟度：** PROVISIONAL（同步路徑已定案；非同步預覽模式待產品需求決定）
> **對應 DOCX 章節：** 13

---

## 4.1 正式同步路徑

```
使用者輸入
  → Request Gateway（驗證輸入、同意、流派、任務、時間尺度）
  → Chart Normalizer（生成 canonical JSON 與 input_hash）
  → A Truth Service（產生 truth_package，必要時多樣本一致性）
  → Planner（拆解為原型單元 + 全篇弧線 + 三條跨感官 Few-Shot）
  → B Narrative Service（分段生成；每段寫入 story_state 與 trace）
  → C Scorer（段落評分；硬紅重生成或終止，黃燈標記，綠燈繼續）
  → Global Reviewer（完整讀取全文，重新計算全局 100 維與逃逸）
  → Safety Service（獨立終檢）
  → Assembler（輸出人類可讀版本，保存全部版本與評分事件）
```

---

## 4.2 段落級狀態

B 的生成狀態由 `story_state` 追蹤：

```yaml
story_state:
  case_id: str
  global_arc: [建立, 堆疊, 轉折, 收束]
  current_unit: AU-03
  completed_units: [AU-01, AU-02]
  emotion_temperature_curve: [0.2, 0.25, 0.4]
  motifs:
    - name: 門
      uses: 2
      angles: [童年仰視, 成年外部凝視]
  last_hook: str
  forbidden_escape: [安慰性逃逸, 模板化逃逸]
  segment_index: 7
```

## 4.3 情緒鉤

每段末尾產生情緒鉤，下一段從鉤子續接，避免機械拼裝。

- **格式：** 段落最後一句話，包含情感張力或懸念
- **鉤子類型：** 情感鉤（情緒延續）、問題鉤（引發好奇）、意象鉤（意象回響）
- **失敗處理：** 若 C 判斷鉤子無效（C-23 紅燈），B 重新生成該段末尾
- **避免模板化：** 同一 case 中不得連續使用相同鉤子類型

---

## 4.4 三條跨感官 Few-Shot

Planner 為每個 case 選取三條不同感官通道的 Few-Shot：

1. **視覺主導：** 以畫面、顏色、空間描述為主
2. **情感/內省主導：** 以情緒、內心感受、價值判斷為主
3. **行動/敘事主導：** 以事件、時間推進、因果為主

三條 Few-Shot 的目的是保留 B 的自由度，而不是限制 B 的風格。

---

## 4.5 去過標記

去過標記是一個防止意象同角度重複的工程狀態，而不是創作規則。

- **冷啟動前 ~1,000 次生成：** 只記錄、不硬阻擋
- **等 B 穩定後：** 逐步要求相同原型切換感官、視角或時間
- **啟用時點：** 暫定，需觀察 B 的實際表現後決定

---

## 4.6 同步 vs 非同步

| 模式 | 延遲 | 真理風險 | 適用場景 |
|------|------|---------|---------|
| **完全同步** | 高（A+B+C 串行） | 低 | 正式產品、標準解盤 |
| **前端預覽 + 後台驗證** | 低（先出草稿） | 中 | 需明確標示「未經 A/C 驗證」 |
| **純非同步** | 低（先回 taskId） | 低 | 重型報告、批量處理 |

正式產品建議走完全同步路徑。非同步預覽模式需產品需求決定是否實作。

---

## 4.7 失敗降級

| 故障點 | 降級策略 |
|--------|---------|
| A 低信心/OOD | 停止裝懂；顯示可確定部分與未知；必要時轉專家佇列 |
| B 連續紅燈 | 降低創作溫度、縮小段落、重建大綱；仍失敗則輸出 A 的技術版 |
| C 高不確定黃燈 | 進 D/人類；不能因平均分高直接放行 |
| D 無法判斷 | 輸出低信心與替代解釋，禁止修改 C |
| Safety 觸發 | 根據風險改為直接、清楚、不浪漫化的安全回覆 |
