## 7.1 C→D 觸發流程

```
C 評分完成
  → 全部綠燈 → 正常輸出
  → 任何紅燈 → 終止輸出，進 Safety 或人類
  → 任何黃燈 → 觸發 D
```

D 被觸發後：

1. 讀取 A 精簡包（200–500 字）
2. 讀取 B 全文（5,000–8,000 字，一字不刪）
3. 讀取 C 評分報告（30+ 結構化段落 + 100 維評分）
4. 檢索歷史案例（相同維度、相同原型、已批准/駁回的提案）
5. 輸出 0–3 條提案

---

## 7.2 D 的閱讀順序

1. **第一遍：** 只讀 B 全文，不標記，建立整體節奏、情緒弧線、視角與結尾感受
2. **第二遍：** 帶著 A 的核心原型與 C 的黃燈，定位「局部評分」和「全局閱讀」不一致的地方
3. **分辨問題來源：** C 閾值僵化、B 真失誤、A 原型含糊、資料 OOD、或目前無法確定

## 7.4 A/B 投票（僅諮詢）

- **A 的票：** 回答「這個 C 修改會不會損害原型保真」
- **B 的票：** 回答「這個修改會不會不必要地縮窄敘事空間」
- **冷啟動期：** 所有人類裁決
- **後期：** 投票只用於排序與信心輔助，提案仍需歷史回放與 canary

---

## 7.5 人類裁決

| 欄位 | 內容 |
|------|------|
| 案件摘要 | A 核心、B 全文閱讀連結、C 黃燈、D 提案、相似歷史案 |
| 三鍵裁決 | 批准／駁回／需要更多案例 |
| 理由欄 | C 閾值錯、B 真失誤、A 含糊、資料 OOD、偏好不等於真理 |
| 作用範圍 | 單案例外／原型分群規則／全域規則；默認不得全域 |
| 回滾視窗 | 任何批准都可在 canary 指標惡化時撤銷，並保留原規則 |

---

## 7.6 回測、Canary、回滾

### 回測

每次規則修改前，在歷史案例上回放：

- 誤殺率（原本綠燈的案例被新規則判紅）
- 漏放率（原本紅燈的案例被新規則判綠）
- 黃燈召回率（原本黃燈的案例被新規則正確處理）
- 分群偏差（新規則是否對特定流派/任務不公平）

### Canary

- 新規則先部署到 5% 流量
- 監控指標：紅燈正確率、黃燈正確率、人類干預率、使用者滿意度
- Canary 週期：至少 7 天或 100 個案例

### 回滾

- 任何 canary 指標惡化 >10% → 自動回滾
- 回滾後保留新規則的資料，用於後續分析
- 同一規則被回滾兩次 → 需人類裁決是否繼續嘗試

---

## 7.7 黃金分歧處理

當 A 低分、C 低分、但人類喜歡時：

1. 確認 A 低分原因：真理錯、流派差異、保守邊界、還是 A 沒理解新意象
2. 確認 C 低分原因：逃逸、安全、局部閾值、存在姿態，還是相似度空間落後
3. 分類人類喜歡原因：客觀準確、延伸思考、深度共情、內心話、善意謊言、糜爛共情、文學新奇
4. 等待延遲訊號：15 天後是否仍選擇、是否願意指出具體準確處、是否在結果發生後仍成立
5. 決定去向：A 真理修正、B 佳作、C 例外規則、只作情境安慰，或拒絕納入

## 7.8 模型更新頻率

- **C 門檻校準：** 每累積 100 個人類裁決
- **D 版本更新：** 每累積約 100 條人類裁決建立候選版本；是否更新由事件門檻而非日曆決定
- **A/B 模型更新：** 需完整回測 + Canary + 回滾
- **E 實驗：** 獨立於主版本，影子模式運行
