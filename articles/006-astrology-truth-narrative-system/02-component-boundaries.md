# 02｜元件邊界

> **成熟度：** SETTLED（核心契約）；PROVISIONAL（模型規模建議）
> **對應 DOCX 章節：** 4–10

---

## 2.1 元件契約總則

每個元件遵循以下契約格式：

- **Identity：** 身份、模型規模建議、訓練資料來源
- **Allowed：** 允許讀取、輸出、修改的範圍
- **Forbidden：** 禁止操作（不可被任何配置覆蓋）
- **Failure Modes：** 已知失敗模式與對應行為
- **Fallback：** 降級策略

---

## 2.2 A：Truth Engine（真理引擎）

### Identity

- **角色：** 從結構化星盤推演占星真理，產生可追溯、可驗證的結構化判斷
- **模型規模建議：** 13B–31B（需實驗 A1 決定）
- **訓練資料：** 六層資料中的 A 視圖（結構化輸入 + 可審計真理報告）
- **輸出格式：** 結構化 `truth_package`（JSON）

### Allowed

- 讀取：結構化星盤、流派知識庫、歷史案例、A 視圖訓練資料
- 輸出：`truth_package`（含因果鏈、信心、不確定性、流派來源、邊界條件）
- 修改：自己的推論參數、版本、內部一致性校準

### Forbidden

- 輸出敘事文本（這是 B 的責任）
- 直接控制 B 的生成內容
- 修改系統憲法
- 隱藏不確定性（低信心時必須標記）

### Failure Modes

| 模式 | 行為 |
|------|------|
| 低信心 (<0.6) | 輸出可確定部分 + 未知標記；不硬湊判斷 |
| OOD（未見過的流派或配置） | 轉專家佇列；輸出技術版而非敘事版 |
| 內部不一致 | 多樣本投票；不一致時降級為低信心 |
| 模型不可用 | 回退規則引擎 + 靜態知識庫 |

### Fallback

- A 不可用 → 回退規則引擎 + 靜態知識庫，輸出純技術報告
- A 低信心 → 輸出技術版，不硬湊故事；標示「此部分需專家確認」

---

## 2.3 B：Narrative Engine（敘事引擎）

### Identity

- **角色：** 將結構化真理轉化為人類可感受的敘事
- **模型規模建議：** 7B–13B（前端低延遲需求）
- **訓練資料：** 六層資料中的 B 視圖（去除直接符號→固定意象配對）
- **輸出格式：** 分段生成的中文敘事文本

### Allowed

- 讀取：Planner 拆解的原型單元、三條跨感官 Few-Shot、story_state
- 輸出：分段敘事文本（含情緒鉤）
- 修改：自己的生成參數（溫度、視角、感官通道）

### Forbidden

- 直接讀取 A 的原始 `truth_package`（只能透過 Planner 拆解後的原型單元）
- 添加 A 未指定的占星判斷
- 為了流暢而隱藏不確定性或矛盾
- 使用已被 C 標記為逃逸的敘事模式

### Failure Modes

| 模式 | 行為 |
|------|------|
| 連續紅燈（C 評分） | 降低創作溫度、縮小段落、重建大綱 |
| 仍失敗 | 輸出 A 的技術版，不硬湊故事 |
| 情緒鉤斷裂 | 重新規劃段落邊界，從上一個成功鉤子續接 |

### Fallback

- B 連續失敗 → 輸出 A 的技術版 + 標示「敘事生成暫不可用」
- B 部分段落低分 → 僅重寫該段落，保留前後文

---

## 2.4 C：Control Plane（控制面）

### Identity

- **角色：** 測量 A 與 B 的距離，執行 100 維控制，標記不確定性
- **模型規模建議：** 7B–13B（評分頭 + 規則引擎混合）
- **訓練資料：** 六層資料中的 C 視圖（A/B 對 + 100 維人工/規則標註 + 交通燈結果）
- **輸出格式：** 結構化評分報告（JSON）

### Allowed

- 讀取：A 的 `truth_package`、B 的段落、story_state
- 輸出：100 維評分 + 交通燈結果 + 不確定性標記
- 對任何維度報黃燈（即使不確定）
- 對安全與逃逸維度報紅燈

### Forbidden

- 修改 A 或 B 的輸出
- 用加權平均分覆蓋紅燈
- 在沒有不確定性標記的情況下輸出高分
- 自行決定處置動作（紅燈的處置由 Governance 決定）

### Failure Modes

| 模式 | 行為 |
|------|------|
| 高不確定性黃燈 | 進 D/人類；不能因平均分高直接放行 |
| 維度資料不足 | 該維度自動黃燈，標記「資料不足」 |
| 評分頭不可用 | 回退規則引擎（僅計算可規則計算的維度） |

### Fallback

- C 不可用 → 僅執行安全與逃逸規則檢查，其餘維度全部黃燈
- C 部分維度不可用 → 該維度黃燈，其餘正常

---

## 2.5 D：Governance Assistant（治理助手）

### Identity

- **角色：** 替 B 的完整敘事辯護，替人類把規則修改案壓縮成可裁決提案
- **模型規模建議：** 31B–70B（需要長文本理解能力）
- **訓練資料：** 六層資料中的 D 視圖（A 精簡 + B 全文 + C 黃燈 + 人類最終裁決）
- **輸出格式：** 結構化提案（JSON）

### Allowed

- 讀取：A 精簡包、B 全文（一字不刪）、C 評分報告、歷史案例
- 輸出：0–3 條提案（含條件、證據、信心、替代觀點）
- 在沒有足夠證據時輸出空提案

### Forbidden

- 在沒有讀完 B 全文前輸出提案
- 為了有用而硬改規則
- 把單一故事的例外直接改成全域放寬
- 修改 A、B、C 的輸出

### Failure Modes

| 模式 | 行為 |
|------|------|
| 無法判斷 | 輸出空提案 + 說明為何不改 |
| 低信心提案 | 強制人審 + 必填 alternative_view |
| 格式錯誤 | JSON schema 驗證失敗 → 返回空提案 + 保存原文 |

### Fallback

- D 不可用 → 所有黃燈直接進人類裁決
- D 提案格式錯誤 → 忽略該提案，保留原始資料

---

## 2.6 E：Semantic Bridge（語義橋接）（研究階段）

### Identity

- **角色：** 將 A 的語義壓縮為向量，與 B 的文本向量對照
- **模型規模建議：** 待定（需實驗）
- **訓練資料：** 六層資料中的 E 視圖（高品質 A–B 對齊對）
- **輸出格式：** 1024 維向量

### Allowed

- 讀取：A 的 `truth_package`（E_truth）、B 的全文（E_text）
- 輸出：向量表示 + 相似度分數
- 以影子模式運行（不影響放行）

### Forbidden

- 在未達到 5000 組對齊資料前影響放行決策
- 用 E_text 的資料回頭改寫 E_truth 的真理座標
- 讓 CosSim 成為唯一評分標準

### Failure Modes

| 模式 | 行為 |
|------|------|
| 向量服務不可用 | 不影響主流程；C 的 CosSim 維度標記為「資料不可用」 |
| 多樣性下降 >10% | 停止 E 實驗，回滾至無 E 狀態 |

### Fallback

- E 不可用 → 系統在無 E 狀態下正常運行（C 的 CosSim 維度停用）

---

## 2.7 Human（人類）

### Identity

- **角色：** 憲法守護者、最終裁決者、制度設計者
- **不可被代理覆蓋的權力：** 最終裁決、憲法修改、例外批准

### Allowed

- 讀取：A 核心、B 全文、C 黃燈、D 提案、歷史案例
- 裁決：批准／駁回／需要更多案例
- 定義新維度、修改門檻、處理流派衝突

### Forbidden

- 逐篇全維度打分（長期角色應從執行者轉為制度設計者）

---

## 2.8 Safety（安全層）

### Identity

- **角色：** 獨立底線檢查，不可被任何元件繞過
- **不可被多數決覆蓋**

### Allowed

- 讀取：B 的輸出全文
- 紅燈：直接終止輸出，不經由 C/D 投票

### Forbidden

- 被 A/B/C/D/E 的投票結果覆蓋
- 在紅燈時允許「先輸出再修正」

---

## 2.9 元件間通信限制

```
A ──truth_package──→ Planner ──原型單元──→ B
                                                    ↕
A ──truth_package──→ C ←──B 段落── B
                      ↕
C ──黃燈──→ D ←──B 全文── B
              ↕
D ──提案──→ Human
              ↕
Human ──裁決──→ D/C/A/B
```

- A 與 B：不直接通信（經由 Planner 拆解）
- B 與 A：不回饋（B 的輸出不修改 A 的真理）
- C 與 D：C 報黃燈觸發 D，D 提案修改 C 的規則
- E：影子模式，不影響主流程

---

## 2.10 模型規模建議與實驗需求

| 元件 | 建議規模 | 實驗需求 | 優先級 |
|------|---------|---------|--------|
| A | 13B–31B | 實驗 A1：13B Full FT vs 31B DoRA | 高 |
| B | 7B–13B | 前端延遲測試 | 高 |
| C | 7B–13B | 評分頭 vs 規則引擎混合驗證 | 高 |
| D | 31B–70B | 長文本理解能力測試 | 中 |
| E | 待定 | 需 A/B 穩定後才能啟動 | 低 |

模型規模建議不是架構前提。先租雲端 GPU 跑實驗，根據結果決定買斷設備。
